# Bounded parallel original-script runner

Integrated base source: `44ad2139a4f029a7639648d15f6db41d9913ea98` (harness-only change); serial/parallel baseline comparison used earlier `c5c7dd9059aade5f3c616892fcb3e6e3efc75feb`. The runner now executes up to four independent original scripts per C/Rust phase while retaining input-order results and the existing per-script PTY timeout. It initializes the shared `test/tmp/.git` once before workers start; otherwise fresh concurrent `libtest.sh` instances race to run `git init`. Jobs are submitted in a bounded queue, so an unexpected worker error cannot leave all 154 scripts queued. C still runs before Rust, and another suite must not run in the same checkout concurrently.

Checks: Python compilation and runner negative self-test pass. Eight unchanged scripts (graph, main, stage, tree, blame, grep, refs, reflog) pass with `--jobs 1` and `--jobs 4`: C and Rust each pass 8/8 scripts and 44/44 original assertions; ordered per-script status, checks, assertion mappings and executable hashes match. Four known failing scripts still produce `BLOCKED` with six failed Rust assertions, not a false pass. With the shared dummy Git repository temporarily absent, a two-script parallel C/Rust run passes and creates it before worker launch. Independent read-only review found no remaining actionable issues. Temporary JSON results were not committed.
