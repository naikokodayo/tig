# Tig → Rust 全量迁移执行计划

目标是以安全、惯用的 Rust 完整实现原版 Tig 的用户行为，并保留原项目来源、历史和 GPL-2.0-or-later 许可。迁移完成前，C 实现仍是行为基准，Rust 版本标记为进行中。

## 当前阶段门

最新严格配对快照固定在已合并源码 `3fb38278`：154 个未改动的原版脚本在 C 与 Rust 两侧均实际尝试，Rust 应用与图形辅助程序均由 Rust 构建。C 为 152 通过、0 失败、2 跳过；Rust 为 **148 通过、4 失败、2 跳过**。Rust 的 572 条断言全部实际执行，566 通过、6 失败；没有新增失败。完整二进制哈希、原始输出和逐脚本映射见[当前严格配对证据](evidence/upstream-rust-only-current.json)。这次快照覆盖已合并的 `show REV -- pathspec` 过滤；相关真实终端与 Git 回归补足了原版脚本未覆盖的组合。阶段门仍未通过，最终应用 benchmark 延后。

## 并行任务与合并顺序

任务在各自克隆和特性分支中实施，向 `naikokodayo/tig:main` 提交 PR；主任务逐个独立复审、及时合并。不要并发修改同一个检出目录的 `rust/main.rs`。

### 快速完成 Rust 功能面

先以现有 C-free `cargo build --locked --release` 作为 Rust 入口，按用户工作流补齐 grep、refs、配置、命令、树与暂存等子系统；每条并行任务独占文件，交付可用功能并删除被替代的 Rust 分支。每个 PR 跑相关原版脚本和真实终端/索引安全回归，合并数个子系统后再跑一次完整 154 脚本。内部 Git trace 的逐字差异不阻塞功能实现，但仍记录为原版断言失败；路径、索引和外部命令的安全校验不延期。完成可用功能面后集中处理其余行为差异，再进行最终应用 benchmark。C 实现暂留作可运行基准，阶段门关闭后成批移除，不用重复造一份 C 兼容层。

grep、refs、状态回退、文件查找、自动刷新、提示补全和通用视图导出均已接入 Rust UI。下一批优先补可见的导航与操作缺口，再集中处理剩余断言差异。每批只交付可调用的工作流，不把 Rust/C 源码行数当作完成率。

1. **已合并并通过全套**：标准输入、diff 统计、分支变量、Git alias、控制字符、blame 初始差异、布局、子模块 diff 选项、主视图选项及暂存分块显示。
2. **提示历史与补全已合并**：加载、上下导航、限额、去重和 Tab 补全有真实终端回归；原始 `main/search-preload` 已通过。`--version` 只声明 readline 风格的历史与补全，不声称 GNU Readline 链接或完整行编辑等价。
3. **剩余四个失败脚本**：`diff/diff-highlight` 缺失程序时 Rust 保留原 diff 并报错；`main/filter-args` 与 `status/file-filter` 尚有三条内部 Git 命令逐字 trace 差异，屏幕断言均通过；`tree/file-name` 见下方安全差异。原始断言没有修改。为满足 trace 而增加无用 Git 调用不作为迁移目标。
4. **结构剪枝已取得可验证结果**：运行时 C 头文件解析已由 Rust 目录替代；仅用 `Cargo.toml`、`Cargo.lock`、`rust/` 和 `tigrc` 的 C-free release 构建通过。C 源码和原版测试仍作为行为基准保留，等阶段门完成后再移除。

`tree/file-name` 是单独的安全差异：C 的 `git ls-tree` 文本输出对非 ASCII 文件名加引号和转义，随后 `src/tree.c` 按原始目录名的字节长度从该文本剥离路径，导致测试所期待的截断/乱码行。Rust 使用 `-z` 保留真实路径字节并正确显示文件名；真实 Git 回归已核对名称、路径与历史元数据。复制 C 行为会破坏文件导航。保留原版失败断言与原始证据，不修改测试或降低路径安全要求；阶段门继续保持阻塞，待明确验收该例外。

每个 PR 只跑受影响的原版脚本、安全回归及 Rust 检查，并保留一份源码/二进制绑定的最终凭据。多个已复审切片合并后再跑完整 154 脚本，避免反复构建和提交近似 JSON。被新快照取代的全量收据从当前树删除，历史仍由 Git 保存。最后再做跨平台与性能验收。

## 完成标准

- 原版 154 个脚本在等价环境下逐项核对；Rust 行为失败为零。每个跳过项写明依赖与重跑方式，不能因提前退出漏计。
- 图形辅助路径不再借用 C 的输出，所有结果确认为 Rust 应用行为；原版 C 基线和 Rust 结果保留原始日志与机器可读收据。
- 保持 `#![forbid(unsafe_code)]` 的第一方 Rust 边界，路径、补丁和外部命令的输入验证不降低；不支持的操作明确拒绝，不静默执行相似但不同的操作。
- Linux 与 macOS 的格式、单元测试、Clippy、release 构建和真实终端交互通过；常见终端尺寸、信号、长时间 Git 子进程及大仓库内存行为经专项验证。
- 来源、历史、版权、许可和使用文档正确；稳定的 Rust 入口可以替代 C 入口后，才考虑移除 C 代码。

## 完成后基准测试

全量行为门关闭后，在同一机器、同一 Git 版本、相同仓库快照和终端尺寸下，对原版 C 与 Rust 的**完整应用**重复执行相同工作负载：启动至首屏、主视图滚动/搜索、diff、blame、refs、tree、status 与暂存。每个工作负载先验证屏幕及 Git 索引/工作树结果等价，再交替预热和多次正式计时，记录中位数、p95、峰值 RSS、CPU、二进制大小、构建条件和原始样本。当前 [组件 benchmark](BENCHMARK.zh-CN.md) 只测提交图辅助程序，不能替代这份最终报告。
