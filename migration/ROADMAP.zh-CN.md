# Tig → Rust 全量迁移执行计划

目标是以安全、惯用的 Rust 完整实现原版 Tig 的用户行为，并保留原项目来源、历史和 GPL-2.0-or-later 许可。迁移完成前，C 实现仍是行为基准，Rust 版本标记为进行中。

## 当前阶段门

最新严格配对快照固定在源码 `86ce7680`（差异视图、引用过滤、树路径合并后，状态/trace 与配置改动合并前）：154 个原版脚本在 C 与 Rust 两侧均实际尝试，且 Rust 应用与图形辅助程序均由 Rust 构建。C 为 152 通过、0 失败、2 跳过；Rust 为 104 通过、47 失败、3 跳过。Rust 达到的真实断言为 475 通过、82 失败，另有 15 条相对 C 未执行；19 条非断言失败记录单独计数。较早快照为 Rust 95 通过、56 失败、3 跳过。完整二进制哈希、原始输出和逐脚本映射见 [最新严格配对证据](evidence/upstream-rust-only-after-refs-tree-diff.json) 与 [较早快照](evidence/upstream-rust-only-after-main-date-prompt.json)。该结果不是当前主分支的成绩；后续集成检查仍在进行。阶段门保持开启，最终应用 benchmark 延后。

## 并行任务与合并顺序

任务在各自克隆和特性分支中实施，向 `naikokodayo/tig:main` 提交 PR；集成任务逐个审查和合并，避免共享检出与 `rust/main.rs` 产生并发覆盖。

1. **状态视图**：合并冲突、邮件应用、静默外部命令的状态更新。当前集成任务负责独立复核、完整原版测试和提交。
2. **差异视图**：使 `diff-context` 和 `--word-diff` 在实际 Git 调用、刷新及返回主视图时生效。独立 Codex 任务，较高推理强度；以原版两个 diff-context 脚本为首批验收。
3. **责备视图**：补齐 Git blame 的时间、时区、历史文件名与配置列渲染。独立 Codex 任务，最高推理强度；先验收 default/start-on-line 截图，并保持历史路径不能误用于工作树编辑。
4. **配置解析**：对齐原始路径警告、展开路径汇总，以及有证据的解析差异。独立 Codex 任务，中等推理强度；先验收 source/parse 脚本，再检查相关配置回归。
5. **开源复用审查**：逐个核对候选库的维护、许可、最低 Rust 版本和能够关闭的真实测试缺口。独立只读任务，较低推理强度。已有库能在安全边界内解决问题时优先复用；不为抽象的“Rust 化”增加依赖。
6. **测试路由与收据**：让原版应用脚本和图形辅助程序明确走 Rust 路径，核查缺失的 `filter-args` 收据，并用故意失败验证判定器。独立 Codex 任务，较高推理强度；它决定后续完整测试能否作为最终验收证据。
7. **日期兼容**：以原版日期脚本为边界，核对时间、时区、相对日期和配置；评估符合 Rust 1.81 与许可证要求的 Chrono 小组件，能减少自写逻辑时才引入。独立 Codex 任务，较高推理强度。
8. **暂存与局部补丁**：聚焦暂存、取消暂存、局部行和块更新的原版失败，保持路径验证与索引原子更新。独立 Codex 任务，较高推理强度。
9. **引用视图**：聚焦 refs 筛选、分支切换、变量替换及引用交互，验证 Git 调用安全性。独立 Codex 任务，中等推理强度。
10. **主视图图形与导航**：聚焦 goto、图形参数、竖线及刷新等同根因差异，不以 C 图形辅助结果冒充 Rust 验收。独立 Codex 任务，较高推理强度。

上述 PR 按可审查的切片依次集成。每次集成都重新构建最终二进制，运行受影响的原版脚本、安全回归、Rust 检查和完整原版测试；证据绑定提交及二进制哈希。新失败按根因拆成下一批任务。后续覆盖主视图/图形/日期与刷新、差异及暂存、责备导航、引用与目录、配置/命令/CLI、终端输入/颜色/搜索，再做跨平台与性能验收。

## 完成标准

- 原版 154 个脚本在等价环境下逐项核对；Rust 行为失败为零。每个跳过项写明依赖与重跑方式，不能因提前退出漏计。
- 图形辅助路径不再借用 C 的输出，所有结果确认为 Rust 应用行为；原版 C 基线和 Rust 结果保留原始日志与机器可读收据。
- 保持 `#![forbid(unsafe_code)]` 的第一方 Rust 边界，路径、补丁和外部命令的输入验证不降低；不支持的操作明确拒绝，不静默执行相似但不同的操作。
- Linux 与 macOS 的格式、单元测试、Clippy、release 构建和真实终端交互通过；常见终端尺寸、信号、长时间 Git 子进程及大仓库内存行为经专项验证。
- 来源、历史、版权、许可和使用文档正确；稳定的 Rust 入口可以替代 C 入口后，才考虑移除 C 代码。

## 完成后基准测试

全量行为门关闭后，在同一机器、同一 Git 版本、相同仓库快照和终端尺寸下，对原版 C 与 Rust 的**完整应用**重复执行相同工作负载：启动至首屏、主视图滚动/搜索、diff、blame、refs、tree、status 与暂存。每个工作负载先验证屏幕及 Git 索引/工作树结果等价，再交替预热和多次正式计时，记录中位数、p95、峰值 RSS、CPU、二进制大小、构建条件和原始样本。当前 [组件 benchmark](BENCHMARK.zh-CN.md) 只测提交图辅助程序，不能替代这份最终报告。
